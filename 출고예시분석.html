🤔 먼저 정할 것 — 바스 행의 '오더발행일'을 어쩔까
발주 예상은 오더발행일 기준이고, 그건 출고일 − (리드타임−1)영업일로 역산한 값임.
그런데 바스는 리드타임이 무의미함. 출고일을 우리가 임의로 정하고, 납품서를 열어야 납품요청일이 찍히기 때문(바스 대화방에서 확인).
지금은 바스 행에도 리드타임이 돌아가서 오더예상일이 계산되고 있음 → 그 숫자는 의미 없음.
선택지: ① 숫자 안 보이게 막기 ② 보이되 '참고용' 표시 ③ 그냥 두기. → 아직 미정. 결정 후 반영할 것.

✅ 끝난 것
· 날짜 라벨 버그 — 엑셀 라벨이 잘림(7.1=7/10, 7.2=7/20). 예전 코드는 잘린 라벨 컬럼을 통째로 버려서 7/10·7/20·7/30·8/10 물량이 증발했음. 이제 라벨을 안 읽고 첫 컬럼=asof, 순서대로 +1일로 복원(33일치).
· 오이도/그레이박스 키 충돌 — 코드가 같아서 나중 파일이 앞 창고를 덮어썼음. 키를 code|oido|shipDate로 수정.
· 벤더 구분 + 중복 제거 — 드림 예시에 와이비 품목 41개가 섞여 들어옴. 규칙: 와이비 전량 + 드림 중 와이비에 없는 코드만. (데이터·백업 탭에 현황·토글)
· 바스 분류 — 바스 = 드림에 있고 와이비에 없는 코드. 접두사 하드코딩 안 함.
· 발주 예상이 스냅샷 하나만 보던 버그, 리드타임 3종 수정(3·3·5일), 7/17 제헌절 추가.
· (7/15) 정오더 6,672건 실측 반영 — 5/1 근로자의날 추가(5/6은 영업일), 유리장식 비규격 6일 분기 신설, (비) 접두 비규격 판정 추가, 주말당김 함수가 공휴일 무시하던 버그 수정(7/18토→7/17 제헌절로 증발).

① 납품서 대조 탭
parseDelivText(index0708.html, 72PDF/487건 검증)를 이식. 대조 키 = 제품코드 + 창고(오이도/그레이) + 출고일. 납품서엔 납품요청일이 찍히므로 +2영업일 해서 출고일로 환산. ※ 빌트인 전용. 바스엔 적용 금지.

② 적중률 — 예시표 "오늘 칸"이 확정분
예시표는 뽑은 날부터 시작하고, 오늘 칸은 이미 발주서가 나온 확정 물량. 내일 이후만 예측.
어제 스냅샷의 '오늘 칸'(예측) vs 오늘 스냅샷의 '오늘 칸'(확정) → 선행일수별(1·2·3일 전)로 집계하면 적중률이 나옴.
매일 뽑아야 함. 오늘 안 뽑으면 오늘 확정분은 영영 못 잡음.

③ 헛스윙 정의 다시 보기
거래처는 예시만큼 조금씩 소진하다가 뭉텅이로 발주함 (납품서 40~50장 ↔ 예시 12장, 자릿수가 다름). 예시가 그날 안 나왔다고 곧바로 헛스윙 아님 → "지연 적중"과 "진짜 헛스윙"을 갈라야 함.

순서: 🤔 결정 → ① → ② → ③. 한 번에 한 층.
바스 대화방에 넘길 것: 날짜 복원 규칙, 중복 제거 규칙(둘 다 양쪽에 필요).
넘기면 안 되는 것: 리드타임 / 납품요청일 −2영업일 (바스엔 무의미).
먼 훗날: 파서를 ybn-parse.js로 빼서 두 앱이 같이 읽게. 지금은 각자, 규칙만 동일하게.

각 출고일의 수량은 가장 마지막에 조회한 스냅샷 값으로 자동 갱신돼요(최신=최종). 매일 새 파일을 넣으면 그 출고일이 최신값으로 덮어써져요.
예시에 뜬 물량이 진짜 발주로 올지 미리 가늠하는 화면입니다. 한 줄 = 한 품목이에요.
· ● 준비 권장 — 물량이 크거나 늘고 있어요. 미리 만들어두면 안전합니다.
· ● 주시 — 아직 적지만 늘어나는 중. 다음 조회 때 다시 보세요.
· ● 여유 — 급하지 않아요.
「궤적」은 조회할 때마다 이 수량이 어떻게 변했는지예요. 계속 늘어나면 실제 발주로 올 가능성이 높습니다.
예시로 떴던 물량이 실제 출고일에 진짜로 남아있었는지(적중) / 떴다 사라졌는지(헛스윙)를 측정해요. 같은 출고일을 여러 날 조회한 스냅샷이 쌓여야 계산돼요. 리드타임이 멀수록 예시가 흔들리는 정도를 봅니다.
오늘 예시의 '오늘 칸' = 약 90% 확정 발주. 바스만 이 값을 날짜별로 쌓아, 거래처 창고에서 얼마나 빠져나가는지 가늠합니다. 스냅샷을 넣을 때마다 그날 확정분이 자동으로 누적돼요.
바스재고운영에서 이 파일을 불러오면 예시표를 다시 넣지 않아도 됩니다. 두 화면을 같은 주소로 열어두셨다면 파일 없이도 자동으로 넘어갑니다.
발주일 기준으로 봅니다. 품목마다 리드타임이 다르니(글래스도어 2일·정규격 5일·에어힌지 7일…), 각 품목의 출고일 = 발주일 + 리드타임인 예시 물량을 거꾸로 당겨와요. 즉 "이 날 발주가 뜰 것"을 예측합니다.
납품서 PDF를 끌어다 놓기 또는 클릭해서 선택 · 여러 장 한꺼번에 가능 · 오이도/그레이는 납품서 안 납품처로 자동 구분
— 납품서의 납품일이 곧 발주일. 이 발주일 납품서를 전부 묶어, 품목별 리드타임 역산한 예시와 견줍니다.

벤더 중복 처리
한샘 예시표는 벤더별로 따로 나오는데, 드림하이텍 예시표에 와이비앤디 품목이 섞여 들어와요 (업체 이관 과정의 시스템 오류). 그냥 더하면 두 번 세어집니다.
규칙: 와이비앤디 전량 + 드림 예시 중 와이비에 없는 코드만. 와이비를 기준으로 삼아서, 나중에 오류가 고쳐져도 결과가 안 바뀝니다.
되돌릴 수 없어요. 먼저 백업부터 받으세요.
