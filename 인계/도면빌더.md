# 코아스 도면 빌더 — 작업 인계 문서

## 이게 뭔지
코아스(캐비넷도어) 발주용 **드래그 편집 방식 도면 제작 툴**. 단일 HTML 파일(`도면빌더.html`).
목적은 예쁜 도면이 아니라 **발주 코드 → 도면 데이터(JSON) → (다음 단계) 코아스 작업지시서 자동생성**.
즉 도면을 그림이 아니라 재사용 가능한 데이터로 남기는 게 핵심. 그래서 캐드 대신 이걸 씀.

**중요**: 새 채팅에서 이어갈 때, 지금 첨부하는 `도면빌더.html` 파일을 반드시 먼저 업로드해서 현재 상태에서 이어갈 것. 처음부터 다시 만들지 말 것.

## 사용자(예빈) 작업 방식 — 필독
- 코드를 읽지 못함. **완성된 즉시 사용 가능한 파일**을 `present_files`로 전달해야 함.
- 모든 소통은 한국어.
- 앱 기본 테마는 **항상 라이트모드(밝은 배경)**. 절대 다크모드 아님.
- 개발 철학: "한 번에 한 층, 되돌리기 쉽게, 완성 후 다음." 기존 동작하는 코드는 함부로 갈아엎지 말 것.
- 단일 HTML 파일 원칙 유지. 불필요한 리팩터링 금지.

## 기술 스택 / 구조
- 순수 HTML + JS(빌드 없음). SVG로 도면 렌더링(논리좌표 1mm=1px).
- 엑셀 파싱용 SheetJS를 CDN으로 로드: `<script src="https://cdn.jsdelivr.net/npm/xlsx@0.18.5/dist/xlsx.full.min.js">`.
  - **주의**: 이 환경에서 브라우저 테스트 시 jsdelivr 접근 불가. 테스트할 땐 `npm pack xlsx@0.18.5`로 받아 로컬 인라인 교체 후 테스트하고, 배포본은 CDN 유지.
- 상태 저장: `localStorage`
  - `dwgbuilder-v1` = 현재 캔버스 작업본(M)
  - `dwgbuilder-lib-v1` = 발주 라이브러리(LIB)
- 데이터 검증은 반드시 실제 엑셀(`와이비앤디_단가인상_2026_05_12__코아스.xlsx`, 67품목/38그룹)로 할 것.

## 핵심 데이터 구조
```
M = { name, W, H, frame:'유테'|'무테', frameW, elements:[...] }
```
요소(elements) 종류:
- dim(치수선): {type,orient:'H'|'V',x1,y1,x2,y2,value,fs,auto,tick,tox,toy,color,moveMode,overall?}
- pitch(힌지 피치): dim과 유사 + {chainSide:'L'|'R'} (체인 그룹 식별)
- text: {x,y,text,fs,anchor,weight,color}
- arrow(화살표): {x1,y1,x2,y2,color,head:'end'|'start'|'both'|'none',width}
- bore(보링): {kind:'hinge'|'hole',x,y,r,label,color,autoSide?}
- view(확대뷰): {x,y,w,h,title,scale}
- tox/toy = 치수 숫자의 오프셋(선에서 떼기). overall=true는 전체 가로·세로 치수선.

```
LIB = { groups:[ {key, model, spec, color, codes:[{code,lr}], dwgNos, W, H, drawing:M객체|null} ] }
```

## 지금까지 구현된 기능 (전부 동작 검증됨)
1. **모델 입력** — 모델명/가로W/세로H/프레임(유테·무테)/프레임폭 → 비율대로 프레임 자동 렌더.
2. **드래그 편집** — 모든 요소를 마우스로 이동. 끝점(파란 점)·숫자(초록 ↔ 핸들)·리사이즈(확대뷰) 핸들.
3. **요소 추가** — 치수선/텍스트/힌지피치/화살표/힌지보링/관통보링/확대뷰. + "전체 가로·세로 치수선" 버튼.
4. **힌지 자동배치** — 변(좌/우)·개수·변에서거리 → 균등 분배 후 드래그 미세조정.
5. **힌지 피치 체인** — 세로로 늘어선 힌지에 대해 [프레임상단→힌지들→프레임하단] 세로 치수 체인 자동생성.
   - "입력값으로 생성"(예: `100,295,295,250` → 그 간격대로 힌지 배치+체인) / "힌지 간격으로 자동"(현재 힌지 위치에서 읽음).
   - 체인은 **그룹 이동**: 한 세그먼트를 끌면 전체가 같은 x 유지하며 함께 이동, y경계(힌지) 고정 → 정렬 안 깨짐.
6. **오브젝트 스냅(OSNAP)** — 토글. 프레임 4모서리+변중앙+보링중심에 달라붙음. 반경 화면 28px.
   - **축 정렬 스냅**: 다른 점과 같은 세로선/가로선에 오면 그 축에 맞추고 초록 점선 가이드 표시(캐드식).
   - 요소 전체 이동 시에도 가까운 끝점이 스냅됨.
7. **속성 패널(우측)** — 선택 요소의 값 정밀 조정. 치수 숫자 4방향 미세이동 패드(▲◀▶▼, 2mm씩, tox/toy 둘 다).
   기호 삽입 버튼(Ø ⌀ ⊕ × ° 피치 관통 등), 색상 프리셋(검정/빨강/파랑/초록/주황)+커스텀.
8. **발주 라이브러리** — 코아스 엑셀 업로드 → 좌우 교집합 매칭 → 그룹 목록.
   - 매칭키 = **모델+규격+색상** (모델명만으론 안 됨). 좌우 판별 = 품명의 (L)/(R)·DOOR-L/-R.
   - 검증됨: 67품목→38그룹(좌우짝28/단독10), EDC0804 8개→4쌍 정확 분리, EEC1801·(특)ZD0000 가짜짝 제외.
   - 각 그룹에 좌도어 기준 도면 1장 그리면 좌·우 코드 양쪽에 매칭. "이 도면 완료" 버튼으로 그룹에 저장.
9. **복사/다른이름 저장**
   - 헤더 "다른 모델로 저장": 현재 도면을 새 모델명으로 라이브러리에 복제(요소 id 새로 발급=독립).
   - 라이브러리 "복사" 버튼: 도면 있는 그룹→도면 없는 그룹으로 복제(규격 다르면 프레임 크기는 대상에 맞춤).
10. **출력** — 저장/불러오기(localStorage), PNG 내보내기, 인쇄(A4 가로), 라이브러리 JSON 내보내기/가져오기.

## 확정된 규칙 / 건드리지 말 것
- 좌우 판별: 품명 (L)/(R) 또는 DOOR-L/-R. 코드 순서로 좌우 추정 금지(ECC0812는 순서 뒤집힘).
- 매칭키는 모델+규격+색상 교집합. 모델명만으로 묶으면 EDC 8개·가짜짝 엉킴.
- 라이트모드 고정. 기존 동작 코드 유지.

## 다음에 할 수 있는 것 (사용자가 고르면 진행)
- **[최우선 권장] 코아스 앱 연동 검증**: 도면 2~3개만 그려 JSON 내보내고, 코아스_작업지시서.html이 그 데이터로
  실제 작업지시서를 뽑는지 먼저 확인. 이게 되면 나머지 그릴 이유가 생기고, 안 되면 방향 전환.
  (JSON 구조: `{groups:[{model,spec,color,codes:[{code,lr}],drawing}]}` → 코드로 조회 가능)
- 가로변 힌지(위쪽에 좌→우 배열) 피치 체인 — 현재는 세로변만.
- 확대뷰 박스 안에 실제 보링 형상 그려넣기.
- 스냅 반경·기본 글자크기 등 수치 미세조정.

## 미해결/주의
- W/H 파싱: 규격의 마지막 3숫자를 가로×세로×두께로 봄. 특이 규격 모델은 도면 열 때 크기 수동 확인 필요.
- 이 환경 이미지 뷰어가 간헐적으로 스크린샷을 안 보여줌 → 데이터(evaluate) 검증을 우선으로.
