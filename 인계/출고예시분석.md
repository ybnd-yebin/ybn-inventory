## 🤔 지금 고민 중인 것 (새 창에서 이어갈 주제)

**바스 행의 '오더발행일'을 어떻게 할 것인가.**

- 3일 대비표는 **오더발행일** 기준으로 보여준다.
  `오더발행일 = 출고일 − (리드타임−1) 영업일`
- 그런데 **바스는 리드타임이 무의미하다.**
  출고일을 우리가 임의로 정하고, 납품서를 열어야 납품요청일이 찍히기 때문.
- 지금 코드는 바스 행에도 리드타임을 돌려서 오더예상일을 계산 중.
  **그 숫자는 아무 의미가 없다.**

선택지:
1. 바스 행은 오더발행일 칸을 비우기 (오해 방지)
2. 보이되 "참고용" 표시 달기
3. 그냥 두기 (사용자가 감안)

> 배경: 바스는 별도 앱 `바스재고운영.html` 소관.
> 이 앱에서 바스는 **"분류해서 보는 것"까지**만 하기로 함.
> 발주점·재고·마감은 여기서 만들지 말 것. 두 앱이 갈라진다.

## ✅ 오늘까지 완료된 것

### 파싱 관련 (버그 수정)

**날짜 라벨 — 물량이 증발하던 버그**
- 한샘 예시표 엑셀은 일자 라벨이 잘려서 나온다.
  `7.1` = 7월 **10**일, `7.2` = 7/20, `7.3` = 7/30, `8.1` = 8/10
- 예전 코드는 정규식 `/^\d{2}\.\d{2}$/`로 걸러서, **잘린 라벨 컬럼을 통째로 버렸다.**
  → 7/10, 7/20, 7/30, 8/10 물량이 안 보였음.
- **해결**: 라벨을 파싱하지 않는다.
  첫 날짜 컬럼(index 11) = `asof`(파일 뽑은 날), 이후 순서대로 **+1 달력일**. 33일치.
  `labelLooksLike()`로 교차검증만 하고, 어긋나면 `console.warn`.
- 컬럼: `dateStart=11`, `dateEnd=43`, `total=44`

**오이도/그레이박스 키 충돌**
- 글래스도어는 두 창고가 **제품코드까지 동일**하다.
- 집계 키가 `code|shipDate`였어서, 나중에 로드된 파일이 앞 창고를 **통째로 덮어썼다.**
  (오이도 물량이 0이 되는 사고)
- **해결**: 키를 `code|oido(O/G)|shipDate`로 변경.
  적용 지점 3곳: `buildLatestByShip`, `buildTrajectories`, `renderMonth`
- 구분 수단: 예시표는 **파일명에 `(오이도)`**, 납품서는 `dest` 필드.

**3일 대비표가 스냅샷 하나만 보던 버그**
- 전체 SNAPS 중 "최신·행 많은" 하나만 골랐다.
  그레이박스 파일이 뽑히면 오이도가 통째로 안 보였음.
- **해결**: 오이도/그레이박스 각각의 최신 스냅샷을 `pickLatest`로 골라 rows를 합침.

### 벤더 / 중복 제거

- 매출처만 둘로 갈림. 생산은 우리 한 곳.
  와이비앤디 `0000819003` / 드림하이텍 `0000812229` (자회사)
- **예시표는 벤더별로 별도 파일**로 나온다.
- 드림 예시 56행 중 **41행이 와이비 예시와 100% 동일** (업체 이관 과정의 시스템 오류, 언젠가 고쳐질 수 있음).

**중복 제거 규칙**
```
전체 소요 = 와이비앤디 예시 전량
          + 드림 예시 중 와이비앤디에 없는 코드만
```
- **반드시 와이비를 기준(신뢰)으로.** 드림 우선으로 짜면, 오류가 고쳐져 드림에서 41개가 사라졌을 때 조용히 망가진다.
- 게이트 함수: `ybndCodeSet()` → `effectiveRows(snap, ybCodes)`
  **이 함수를 거치지 않고 `SNAPS.rows`를 직접 돌지 말 것.**
- `DEDUPE_VENDOR` 토글 + 벤더 현황표를 데이터·백업 탭에 추가.
- CSV는 원본 전량 + `벤더` / `중복제외` 컬럼.

### 바스 분류

```
바스 = 드림 예시에 있고 + 와이비 예시에 없는 코드
```
- 함수: `isBas(row, ybCodes)`
- ⚠️ **코드 접두사(`BB10*`)로 하드코딩 금지.**
  "와이비에 없으면 바스"라야 새 코드 체계가 와도 스스로 적응한다.
- 드림에 섞여 들어온 와이비 품목 41개는 **바스가 아니라 중복제거 대상**이고, 이 규칙이 자동으로 갈라낸다.
- `category(row, ybCodes)`로 시그니처 변경.
  (예전 `category(name, isOido)`는 `categoryByName`으로 분리, 문자열 인자 하위호환 유지)
- 분류 우선순위: `OIDO > BAS > E500/E700/ETC`
- UI: 칩 2곳 + 셀렉트 2곳에 `바스` 추가. 표에서 연파랑(`#d9e8f5`) 행 + `바스` 배지.

### 날짜 규칙

- **납품요청일 = 출고일 − 2영업일** → 대조 시 `출고일 = 납품요청일 + 2영업일`
  (`shipFromRequestDate` / `requestFromShipDate`, `DELIV_TO_SHIP_BIZDAYS=2`)
  달력일 아님. **영업일**.
  ⚠️ **빌트인 전용. 바스에 복사 금지.**
- **2026-07-17 제헌절** 공휴일 재지정 (시행 2026-05-11, 금요일이라 대체공휴일 없음) → 목록에 추가.
- **오이도는 토요일도 출고.** 단 토요일 출고분은 금요일에 선발주 받아 금요일 작업
  → 오더발행일 계산 시 토/일 출고분을 **직전 금요일로 당겨 합산.**
  (`isOido ? pullWeekendToFriday(iso) : iso`)
  오이도 외에는 토/일 출고 없음.

   - 예시표는 뽑은 날부터 시작. **오늘 칸은 이미 발주서가 나온 확정분.** 내일 이후만 예측.
   - `어제 스냅샷의 '오늘 칸'(예측) vs 오늘 스냅샷의 '오늘 칸'(확정)`

   - **매일 뽑아야 함.** 오늘 안 뽑으면 오늘 확정분은 영영 못 잡음.
4. **헛스윙 정의 재조정**
   - 거래처는 예시만큼 조금씩 소진하다가 **뭉텅이로 발주**함
     (납품서 40~50장 ↔ 예시 12장, 자릿수가 다름)
   - 예시가 그날 안 나왔다고 곧바로 헛스윙 아님
   - **"지연 적중"** vs **"진짜 헛스윙"** 을 갈라야 함

## 참고 — 납품서/마감 (바스 쪽에서 확인됨)

- **납품요청일 = 납품서를 연 날** (시스템 자동, 조정 불가)
- **납품일 = 우리가 임의 지정한 출고일**
- 둘 다 우리 행위 시각 → **납품서로는 거래처의 실제 발주일을 알 수 없다.**
- **참조문서번호 = 발주 단위 키.** 같은 번호가 여러 납품서에 걸치면 분할 출고.
- 마감: **납품일 기준**으로 월을 가름. 자재코드별 월합계.
  `마감수량 = 납품량 − 반품량`
