# 비규격 작업지시서 — 인계 문서

> 새 채팅에서 이 문서를 먼저 올리면 이어서 작업할 수 있습니다.
> 작업 대상 파일: **`비규격작업지시서.html`** (직전 출력물)

---

## 1. 이 앱이 하는 일

한샘/영림 **비규격 도어**의 납품서를 넣으면 프레임·유리 치수, 보링, 힌지를 자동 계산해 **작업지시서**와 **유리 발주 리스트**를 만들어 준다. 정규격은 무시하고 비규격만 뽑는다.

**파일 구조**: 단일 HTML 모놀리식. 외부 참조 `ybn-data.js` 1개(MODELS/ASSEMBLY_MODELS/HANSAEM_CATALOG 등 마스터 데이터). ybn-data.js 없어도 파싱·계산은 동작하나 모델 주의사항(asmNoteFor) 매칭은 빈다.

**탭 2개**:
- **📄 납품서 처리** — PDF(납품서) 또는 엑셀(출고정리) 업로드 → 하루치 전체 작업지시서. 파일 확장자로 자동 판별(`isExcelFile`).
- **⚡ 빠른 계산기** — 모델+사이즈만 입력하면 프레임·유리·메모 즉시. 한 줄/여러 줄 입력, HD/OB 타입 선택, 유리 사이즈만 세로열 복사(발주용).

**기본 테마: 라이트모드(밝은 배경) 고정.** 다크모드 쓰지 말 것.

## 2. 비규격 치수 공식 (전부 반영 완료 · 검증됨)

### 프레임(도어) / 유리 차감
| 모델 구분 | 프레임 W/H | 유리 W/H | 비고 |
|---|---|---|---|
| 일반 (M, WT 등) | −5 / −4 | −5 / −7 | 유리 = 프레임에서 both −3 / one −1 |
| WF·WRMB 계열 | −5 / −4 | −5 / −5 | handle:'one' |
| **B** | −5 / **−146** | −5 / **−149** | 납품910→프레임764/유리761. 하부 힌지보링 위치 = 764+(h−910) |
| **BAD** | −5 / **−324** | −5 / **−327** | 납품910→프레임586. 상부고정부 |
| **BC1A · BC1B** | −5 / **납품910 → HD 764 · OB 732** | −5 / −3 | 보링 상부 142 / 하부 110. 도면은 **B 캐드도면 공용** |
| **BD2R** (합적) | 상·하 각 HD380/OB350 | 각 −3 (HD377/OB347) | 유리 1SET(2EA), 상·하 동일 |
| **BD3U** (합적) | 소마이다 HD188/OB173 ×2 + 대마이다 HD380/OB350 | 각 −3 | |

- 코드상 위치: `RULES`(약 212행), `SPLIT`(약 237행), `calc()`(약 291행).
- 합적은 `SPLIT[code][type]`의 `v`값이 **프레임 세로 최종값**. 유리는 `v−3`. `calc`가 `frameSegs`(프레임 분할)와 `glass`(유리, isSet 플래그) 둘 다 반환.
- **B/BAD 로직**: `doorHsub`(프레임 세로 직접차감), `glassHsub`(유리 세로 직접차감) 키로 처리.

### BC1A · BC1B (2026-09-08 사용자 확정 — **코드 반영 완료 · 검증됨**)

- **프레임 세로는 −4로 계산하지 않고 고정값**입니다. **타입에 따라 갈립니다.**

  | 타입 | 납품 910 → 프레임 세로 |
  |---|---|
  | **HD** | **764** |
  | **OB** | **732** |

- 가로는 −5, 유리는 0 × −3 그대로입니다.
- **보링: 상부 142 · 하부 110.**
- **도면은 B 코드의 캐드도면을 같이 씁니다.** BC1A·BC1B 전용 도면을 따로 만들지 마십시오.
  코드 자리는 **`DOOR_ALIAS`** (`{ W2HBT:'M', BC1A:'B', BC1B:'B' }`) — `libDoor()`가 제 도면을
  못 찾으면 이 표를 봅니다. ✅ 2026-09-08 반영.
  HD(764)는 B의 프레임 세로(910→764)와 같은 값이라 자리가 맞아떨어집니다. B도 `hingeBase 764` · `topB 142`입니다.
- 납품 세로가 910이 아닌 것은 아직 규칙을 못 받았습니다. 계산하지 말고 **'확인 필요'로 드러냅니다.**
- **코드 자리**: `RULES.BC1A/BC1B`의 `hSpecial:{HD:{910:764}, OB:{910:732}}` 와, 이를 읽는 `calc()`.
  `calc()`는 `hSpecial`이 `{HD:…,OB:…}` 꼴이면 타입으로 먼저 고르고, **옛 평면 꼴(`{910:732}`)도
  그대로 동작**하게 두었습니다. 다른 모델에 `hSpecial`을 쓸 때 둘 중 아무 꼴이나 됩니다.
- 검증(2026-09-08): `BC1A 445×910 HD → 440×764` · `OB → 440×732`, BC1B 동일.
  회귀 확인 — `B 340×910 → 335×764`, `WT 595×1477 → 590×1473`(384 경고) 그대로.

### WT 힌지 — 늘 4개 (2026-09-08 사용자 확정)

> 출처: WT 캐드 도면(사용자 제공 2026-09-08). **적용 범위 `도어높이 1253~1473`** 이 도면에 적혀 있습니다.

- **WT 계열은 힌지가 항상 4개**입니다. 예전의 "프레임 세로 1473일 때만 4개"는 **틀렸습니다.**
  1473은 개수가 아니라 **간격 a**를 가르는 값입니다.
- 배치는 **위·아래 대칭**입니다 — `110 / a / b / a / 110`. 대칭이라 위에서 읽든 아래서 읽든 같습니다.

| 도어높이(= 프레임 세로) | a | b (중간) |
|---|---|---|
| 1253 ~ 1472 | **320** | **도어높이 − 860** |
| **1473** | **384** | **485** |

- **b는 나머지입니다.** `110+320+320+110 = 860` 이라 `b = 도어높이 − 860`.
  1473도 같은 이치입니다 — `110+384+384+110 = 988`, `1473 − 988 = 485`. **숫자를 손으로 적지 말고 계산해 쓰십시오.**
- 기준은 도면 표기 그대로 **"도어 실높이" = 프레임 세로(fh)** 입니다. 납품 세로가 아닙니다.
  납품 1477 − 4 = 프레임 1473.
- **384가 맞습니다.** 캐드 도면 메모의 `110-380-X-380-110`(380)은 쓰지 않습니다.
  (CLAUDE.md 12-2 · 11-9의 3-B로 남아 있던 "380 vs 384" 항목이 이걸로 정리됐습니다.)
- 보링 사양(도면): 힌지보링 `ø35 × 11.5`, 사전보링 `ø7.8 × 11.5`.
- **도어높이 1253 미만도 힌지 4개**입니다(사용자 확정 2026-09-08). 도면 표의 적용 범위는 1253부터지만,
  개수는 아래로도 4개로 갑니다.
- 도면에 **빨간색** 힌지 4개 + 간격 라벨, 메모에 경고. `calc`의 `hingeSpecial` 플래그.

**WTAP은 예외 그대로 — 비대칭입니다** (WTAP 캐드 도면으로 확인, 2026-09-08)

- 위에서 아래로 `110 / X / 485 / 320 / 110`. **아래쪽만 320**이라 대칭이 아닙니다.
- `110 + 485 + 320 + 110 = 1025` → `X = 도어높이 − 1025`. 지금 앱의 `conv = fh − 1025` 와 같습니다.
- 즉 **"그 외 모든 WT는 110/320/…"에 WTAP은 들어가지 않습니다.** 지금 코드 그대로 두십시오.

- ⏸ 남은 미제는 **[`확인대기.md`](../확인대기.md) B2·B3·B4** — 1253 미만의 a·b, 1473 초과, WTA.

## 3. 표시·집계 규칙 (반영 완료)

- **같은 치수 묶기 + LR 합산**: 같은 프레임+유리+메모끼리 묶어 수량 합산. LR 있으면 `= L2/R3`, 없으면 `= 3EA`. `=` 기호로 사이즈·수량 붙여 가독성↑.
- **합적 SET**: BD2R처럼 상·하 동일하면 프레임 `770 × 380 (상·하 2)`, 유리 발주 `(1SET)` 표기. 발주는 실제 장수(2장)로 합산.
- **유리 발주 리스트**: 같은 사이즈+색상 수량 합산. 버튼 2개 — 「유리 사이즈만 복사(세로열)」(수량만큼 반복, 엑셀 한 열 붙여넣기용), 「표 전체 복사(엑셀)」.
- **색상**: 한글 변환(ETP→에토프, W/Cotton→웜코튼, BRZ→브리즈 등). 카탈로그 비면 제품명에서 추출(`colorFromName`).
- **시리즈**: Grace=유리, Veil=HPM. `seriesOf()`로 판별. **유리/HPM 글씨 배지는 제거함**(AS 배지만 남김). Veil(HPM)은 보라색 네모 틀(`hpm-box`)로 묶고 유리 발주에서 제외.
- **AS**: 납품번호가 **54로 시작**하면 빨간 AS 배지.

## 5. 작업 원칙 (사용자 고정 선호)

- **한 번에 한 층, 되돌리기 쉽게, 완성 후 다음.** 큰 리팩터 금지, 안 깨진 코드 건드리지 말 것.

- **라이트모드 기본** 고정.
- 회사 관계자는 별칭(J 등)으로.
- 모든 수정 후 JS 문법 검증 + 실제 수치로 계산 검증하고 결과를 보여줄 것.

## 6. 검증 스니펫 (참고)

새 채팅에서 계산 검증할 때 쓰는 방식:
```bash
node -e "
const fs=require('fs');const s=fs.readFileSync('비규격작업지시서.html','utf8');
eval(s.match(/const RULES=\{[\s\S]*?\n\};/)[0].replace('const RULES','globalThis.RULES'));
eval(s.match(/const SPLIT=\{[\s\S]*?\n\};/)[0].replace('const SPLIT','globalThis.SPLIT'));
eval(s.match(/function calc\(r\)\{[\s\S]*?\n\}/)[0]); globalThis.calc=calc;
console.log(calc({code:'BD2R',w:775,h:910,type:'HD',handle:'both'}));
"
```
기준값: BD2R 납품910 → HD 프레임380/유리377, OB 프레임350/유리347. B 340×910 → 프레임764/유리761. BAD 600×926 → 프레임602/유리599.

## 7. 납품서 글자 읽기 — 2026-09-15에 막은 구멍 (되풀이하지 마십시오)

시그니처 `(비) 글래스 채널도어 500_연장` 의 규격을 못 읽어 수납도어 작업지시서가 안 나오던 건.
**PDF 글자를 직접 뽑아 보고** 원인을 확정했습니다. 짐작으로 세 번 헛고쳤습니다.

납품서 한 품목이 **세 줄**로 쪼개집니다.
```
( 비 )   글래스   채널도어                          ← 이름 윗부분
1    CAIB13943   1 312894078    000901 그레이박     ← 코드·수량
 500_ 연장 (500*22*2358*0 X)                        ← 이름 아랫부분 + 사이즈
```

| 무엇이 문제였나 | 어떻게 고쳤나 |
|---|---|
| 뒷줄 이어 붙이기가 `비규격`·X형만 알아봄 | `SIZE_HINT_RE` 에 **별표형** 추가 |
| 뒤 두 줄만 보고 **앞줄은 안 봄** | 뒤 2줄 → 없으면 앞 2줄. 코드 있는 줄 만나면 멈춤 |
| 괄호 끝 **`X` 표시**를 몰라 통째로 못 읽음 | 끝 표시를 허용. **닫는 괄호는 그대로 요구** |
| 네 토막을 '0 빼고 남은 둘'로 봄 | **1·3번째가 가로·세로**입니다(`가로*두께*세로*두께`). 두께가 0일 때만 우연히 맞았습니다 |
| `(비)` 는 사이즈 읽기를 아예 안 부름 | `isNonStd()` 로 판정 (괄호 안 공백 `( 비 )` 도 받게) |
| 다시 올려도 **중복으로 걸러짐** | 행을 다 짠 뒤 가릅니다. 이미 있으면 **빈 규격만** 채웁니다 |

**★ 잘린 조각(`(380*0*73`)은 여전히 안 읽습니다.** 닫는 괄호를 요구하는 안전장치이고,
예전에 그걸 읽어 엉뚱한 사이즈가 들어간 사고가 있었습니다(2026-07-24). 풀지 마십시오.

같은 고침이 `index.html` 에도 들어가 있습니다. **두 파일을 같이 고쳐야 합니다.**

## 8. 와이비앤디 앱에서 납품서 가져오기

두 페이지가 같은 주소(`ybnd-yebin.github.io`)라 **브라우저 저장함을 나눠 씁니다.**
`ybn-deliv-v1` 을 그대로 읽어 ROWS 로 바꿉니다 (`ybnReadDelivs` · `ybnDocToRows` · `ybnImport`).

- 행을 짤 때 **이 파일이 PDF 를 직접 읽을 때와 같은 차례**를 씁니다. 한쪽만 다르면 계산이 어긋납니다.
- 이미 가져온 납품번호는 건너뜁니다. 5건 넘게 들어오면 먼저 여쭙니다(`ETP_BULK_ASK`).
- ⚠ **앱이 옛 판으로 읽어 둔 납품서는 규격이 빈 채**입니다. 다시 올리셔야 채워집니다.
  화면의 '읽은 이름'에 그 까닭까지 적어 둡니다.
- 파일을 더블클릭(`file://`)으로 열면 저장함이 갈려 안 보입니다.

## 9. 그 밖 2026-09-15 변경

- **프레임(조립1)** — 발주일 칩으로 골라 보기, 프레임 옆 **유리(참고)** 칸,
  인쇄에서 날짜마다 장 안 넘기고 이어 붙임(`.frm-block`), 고른 날짜만 인쇄.
- **수납도어** — 치수 글자를 빈 칸 **가운데로**(`SUBDOOR_CENTER`: SIG·SIG18·SIGHANG),
  **수량 없는 칸은 지움**(`subdoorDropSlots`).
  ⚠ 지운 칸의 글자는 가운데 셈에서 빼야 합니다. 안 빼면 칸이 짧은 줄 알고 안 내려갑니다.

  베일(HPM) 표시를 보라 → **회색**(`CAD_HPM_LINE`·`CAD_HPM_TEXT`).
  상자로 묶이는 색은 **꺾쇠를 안 그립니다**.
- **인쇄 감춤** — 화면에만 쓰는 칸을 새로 만들면 `@media print` 의 감춤 목록에 한 줄 더하십시오.
  `.ybn-bridge` 를 빠뜨려 인쇄 첫 장이 통째로 안내문이 된 적이 있습니다.
