> 대상: `index.html` 의 **🟠 에토프재고** 탭 · `ybn-data.js` 의 `ETP_SIZE_MASTER` · `SIZE_TO_MODELS`
> 만든 날: 2026-09-14 ~ 09-15
> 숫자·규칙 정본은 `CLAUDE.md`, 미제는 `확인대기.md` 입니다. **여기에 수치를 새로 적지 마십시오.**

## 1. 무엇을 하는 탭인가

에토프 색상 인쇄를 **현성유리에 외주**로 넘겼습니다. 현성이 원판 구매·재단·인쇄를 다 하고
우리는 **완성된 인쇄유리를 사이즈별로** 받습니다. 그 재고를 세는 곳입니다.

- **웜코튼은 계속 우리가 인쇄**하므로 이 탭에 없습니다. 인쇄실(재고관리)에 있습니다.
- 재고는 **사이즈 기준**입니다. 모델별 재고를 만들지 마십시오 — 한 사이즈를 여러 모델이
  나눠 쓰기 때문에 모델로 쪼개면 같은 유리가 흩어집니다. 모델명은 보기로만 띄웁니다.

## 2-1. 인수증 넣기 — 비규격은 들어온 날 그대로 뺍니다 (사장님 확정 2026-09-15)

인수증에 **정규격·비규격이 한 장에 섞여** 옵니다. 둘을 다르게 다룹니다.

| | 장부에 | 왜 |
|---|---|---|
| **정규격** | 입고만 | 납품서가 올라오면 `etpAutoDeduct` 가 알아서 뺍니다 |
| **비규격** | 입고 + **같은 날 소진** (재고 0) | 비규격은 `etpExpandDoc` 에서 아예 제외됩니다(건별 발주라 대표치수뿐). 입고만 넣으면 **영영 안 빠지고 쌓입니다** |

- 비규격 줄에는 **`nonstd:true`** 를 답니다. 이 표식으로 세 곳이 갈립니다:
  **`etpCheckSizes`** 에서 빼고(월평균을 물을 자리가 아닙니다) ·
  **`etpSafetyOf`** 가 0을 돌려주고(안 그러면 받자마자 '부족'으로 잡혀 발주 초안에 오릅니다) ·
  줄에 **「비규격」** 표를 답니다.
- 판별은 **`etpNonStdSizes()`** 한 곳입니다. 같은 치수로 정규격도 오간 적이 있으면 빼지 않습니다.
- ⚠ **인수증을 넣은 뒤에는 「확인 필요」 개수가 늘지 않았는지 보십시오.** 늘었다면
  비규격에 `nonstd` 표식이 안 붙은 것입니다(실제로 3개 → 10개로 늘었던 적이 있습니다).
- **판독을 맞추는 법: 합계 평.** 인수증의 평 = `가로 × 세로 ÷ 90000` 입니다.
  줄마다 세어 합계 평과 맞으면 사이즈·수량을 바로 읽은 것입니다.

## 2-2. 발주를 넣는 길 — 사장님이 직접 넣으십니다 (2026-09-15)

제게 보내실 필요가 없습니다. 세 길 모두 같은 `etpPurchaseOrders` 로 모입니다.

| 길 | 어디서 | 언제 씁니까 |
|---|---|---|
| **발주서 파일 올리기** | 🟠 에토프재고 → `📥 발주서 올리기` | 현성에 보낸 발주서가 **엑셀·PDF로 있을 때**. 가장 손이 적습니다 |
| **발주 탭에서 만들기** | 🧾 발주 → 현성유리 → 3.2T 백사틴 | 발주서를 **새로 만들 때**. 카톡용 이미지까지 나옵니다 |
| 손으로 | 🟠 에토프재고 → `✍️ 넣기` · `📋 붙여넣기` | 입고(인수증)를 넣을 때 |

- **발주 탭에서 저장하면 에토프 발주 기록에도 같이 들어갑니다** — `etpPoFromOrder()`.
  `odSaveOrder()`(손으로 만든 것)와 `odImportApply()`(발주서 엑셀 불러오기) 두 곳에서 부릅니다.
- 걸리는 조건은 **현성유리 + 3.2T 백사틴**뿐입니다(`ETP_PO_LINK_VENDOR` · `ETP_PO_LINK_THICK`).
  대원유리·명그라스의 3.2T 백사틴은 에토프가 아니라 안 걸립니다. 현성 5T 백유리도 아닙니다.
- **사이즈를 옮겨 적지 않습니다.** 발주 탭이 이미 유리 치수를 들고 있습니다 —
  정규격은 모델명을 넣으면 BOM 에서 채워지고(`HD B 4591 L` → `445x761`),
  비규격은 넣으신 값이 곧 유리 사이즈입니다.
- ⚠ **`etpNormSize()` 는 글자가 아니라 꾸러미를 돌려줍니다.** `.size` 를 꺼내 쓰십시오.
  그냥 넣으면 사이즈 자리에 `{size:…, ok:…}` 가 들어가 **같은 사이즈끼리 안 합쳐집니다**
  (2026-09-15 실제로 겪었습니다).
- 에토프 발주 id 는 `etppo_` + 발주 줄의 id 입니다. 어느 발주에서 온 것인지 되짚을 수 있고,
  같은 발주를 고쳐 저장해도 두 벌로 늘지 않습니다.

## 3. 저장하는 곳

| 키 | 무엇 |
|---|---|
| `etpGlassLedger` | 입출고 장부 `{id,d,t:'in'|'out'|'adj',size,qty,src,po,poId,reason,memo,doc}` |
| `etpDeleted` | 지운 줄 묘비 — 없으면 다른 기기에서 되살아납니다 |
| `etpPurchaseOrders` | 발주 기록. 상태는 저장하지 않고 늘 다시 셉니다 |
| `etpSafetyDays` · `etpSafetyOverride` · `etpAvgOverride` · `etpMode` · `etpCutover` · `etpAsChoice` · `etpLotSize` · `etpListBy` | 설정 |
| `etpSeededV1` · `etpPoSeededV1` · `etpPoSeed260914` | 첫 자료를 넣었다는 표식 (건마다 따로) |

동기화는 `metaForSync()` 에 얹어 보내고 `applyMergedFromSheet()` 에서 **줄 단위(id) 병합**합니다.
묘비를 장부보다 **먼저** 받아야 지운 줄이 안 되살아납니다.

## 4. 꼭 알아야 할 함수

| 함수 | 하는 일 |
|---|---|
| `etpNormSize(raw)` | 사이즈 정규화. **큰 수를 앞으로 보내지 않습니다** — `295x345` 처럼 세로가 긴 것이 실재 |
| `etpSizeKeyOf(model,w,h)` | 관통보링(`ETP_LR_SPLIT = /TARG/`)만 `592x693 L` 처럼 좌우를 가릅니다 |
| `etpModelNameOf(it)` | **제품명에서** 모델명을 읽습니다. `CODE_MODEL_MAP` 은 끝의 L/R 이 없어 못 씁니다 |
| `etpBomOf(name)` | BOM 조회. 이름에 L/R 이 없으면 붙여 다시 찾습니다 |
| `etpMeasured({includeAS})` | 납품서로 월평균을 다시 셉니다. AS 포함/제외를 갈라 냅니다 |
| `etpAutoDeduct()` | 정오더는 자동 차감. **AS 는 손으로** (옛 오더 AS 는 자체 인쇄분이라) |
| `etpDeductList()` / `etpApplyDeduct()` | 차감 대기·반영 |

## 5. 지금까지 걸렸던 함정 (되풀이하지 마십시오)

1. **`CODE_MODEL_MAP` 으로 모델명을 읽으면 좌우(L/R)가 날아갑니다.**
   실측: 납품서 60건에서 못 찾은 유리가 170장. 제품명에서 읽으면 2장.
2. **베일(쉐이드·BRZ)은 유리가 아닙니다.** 한샘 카탈로그의 베일 코드 396개는 색상 칸이
   비어 있고, Grace 계열에만 WC/ETP 가 적혀 있습니다. 색이 WC·ETP 인 것만 세십시오.
3. **합적 도어는 유리가 2~3장입니다.** `findModel().glass_w/h` 는 한 장만 압니다. BOM 을 쓰십시오.
4. **비규격은 대표치수뿐입니다.** BOM 으로 빼면 엉뚱한 사이즈에서 빠집니다. 빼지 마십시오.
5. **마이너스 재고를 0으로 깎지 마십시오.** **받은 기록보다 더 나갔다**는 정보입니다.
   ⚠ 2026-09-15 이전에는 "자체 인쇄분으로 만든 몫이라 개시 실사로 메워진다"고 적혀 있었습니다.
   **틀렸습니다** — 자체 인쇄분은 **색이 아예 달라 섞어 쓸 수 없고**, 남은 것은 거의 폐기입니다
   (사장님 2026-09-15). 실사로 메울 수 있는 것이 아닙니다.
6. **`etpAvgOf` 는 `etpAvgOverride` 를 먼저 봅니다.** 마스터에 없는 사이즈를 채워 넣은 값입니다.
