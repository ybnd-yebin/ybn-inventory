## 2. 🏠 오늘 = 오늘의 점검 (예전 홈을 대신합니다)

> "열었을 때 제일 먼저 알고 싶은 것은 오늘 별 문제 없는지, 문제가 있다면 무엇인지.
>  이번 주에 문제될 만한 게 보이는지. 발주를 넣어야 할 게 있는지." (사장님)

**할일 목록에 손으로 적지 않아도 앱이 자료에서 스스로 찾습니다.** 급한 차례로 내려놓습니다.

| 차례 | 무엇 | 함수 |
|---|---|---|
| 📥 | 납품서가 며칠째 안 올라왔는지 — **다른 숫자가 다 여기 기댑니다** | `todayUploadGap()` |
| 🔴 | 오늘 만들 수 없는 것 (유리 부족) | `todayBlocked()` |
| ⏰ | 납기가 지난 발주 | `todayLatePO()` |
| 🟠 | 이번 주(7일) 납품분 중 모자란 것 | `todayWeekAhead()` |
| 🧾 | 현성에 발주할 것 | `etpDraftOrder()` |
| 📋 | 이번 주 할 일 중 안 끝낸 것 | `wkOpenPlans()` |
| ✅ | **걸리는 것이 없으면 '없다'고 적습니다** | — |

**빈 화면을 내지 마십시오.** '문제 없음'과 '아직 안 봄'이 구분되지 않습니다.
`renderToday()` 는 `rerenderAfterSync()` 에서 **늘 다시 그립니다** — 시트 동기화가 끝나기 전에
그리면 '걸리는 것 없음'인 채로 남습니다(실제로 그랬습니다).

## 3. 📋 업무판 — 예전 홈 + 주간 업무일지 · 회의 메모

예전 홈(할일·공지·달력·휴무·오늘작업)을 **그대로** 옮겨 두었습니다. 지운 것 없습니다.
그 위에 노션 「주간업무일지」를 참고해 두 가지를 더했습니다.

| 키 | 무엇 |
|---|---|
| `ybn-weekly-v1` | 주간 업무일지 `{id, week:'월요일 날짜', kind:'plan'|'done', text, at, by}` |
| `ybn-meeting-v1` | 회의 메모 `{id, d, text, at, by}` |
| `ybn-wk-del-v1` | 지운 줄 묘비 |

**적는 값을 만드는 것이 핵심입니다** — 예전 할일이 손이 안 갔던 까닭은 적어도 아무 일이
안 일어나서였습니다. 그래서 이렇게 했습니다. **이 셋을 빼지 마십시오.**

1. 한 줄 치고 **Enter → 바로 들어가고 칸이 비워지고 커서가 그대로** 남습니다.
   회의 메모가 "짧으면 한 줄 길면 열 줄"이라 이게 제일 중요합니다.
2. **담당자·업체·우선순위를 묻지 않습니다.** 혼자 쓰실 때 그 세 칸이 비쌉니다.
3. **이번 주 할 일이 🏠 오늘 화면에 올라옵니다.** 거기서 바로 끝낼 수 있습니다.

## 4. 저장·백업 — 조용히 날아가지 않게

- **`saveAll()` 은 `_put()` 으로 한 칸씩 감쌉니다.** 예전에는 맨몸으로 불러서, 저장함이 차면
  첫 줄에서 멈추고 뒤의 것이 아예 저장되지 않는데 **화면에는 아무 말도 안 나왔습니다.**
  이제 하나가 실패해도 나머지는 저장하고 `_saveReport()` 가 한 번만 크게 알립니다.
  **새 저장 줄을 넣을 때 `localStorage.setItem` 을 직접 쓰지 마십시오.**
- **`exportBackup()` 은 저장함을 통째로 담습니다.** 예전에는 여덟 가지만 담아, 정작 제일 큰
  납품서(1MB)·재고 장부(0.7MB)가 빠져 있었습니다. 지금은 46가지 1,806KB.
- **납품서 월별 정리** (`renderDelivArchive`) — 엑셀로 뽑은 **뒤에** 덜어냅니다.
  ★ 순서를 바꾸지 마십시오. 내보내기가 실패하면 지우지 않습니다.
  이번 달은 정리 대상에서 뺍니다. 지운 납품서는 묘비를 남깁니다.

## 7. 비규격 작업지시서와 앱을 잇는 구조 (2026-09-08 확정 · 2026-10-13 할일.md 에서 옮김)


**결론: 합치지 않습니다. 같은 주소 안의 다른 페이지로 두고 브라우저 저장함을 나눠 씁니다.**
(사장님 제안. 앞서 검토한 "계산을 `index.html`로 이식"보다 낫습니다 — 아래 이유.)

### 7-왜 합치지 않나

| | 크기 |
|---|---|
| `index.html` (와이비앤디 앱) | **870 KB** · 15,332줄 |
| `비규격작업지시서.html` | **442 KB** · 4,117줄 |
| ↳ 그중 **캐드 도면** | 199 KB (**45%**) |

합치면 **1.3 MB**. 현장 휴대폰에서 느려집니다. 무거운 45%는 도면인데 도면은 인쇄해 쓰는 것이라
앱 안에 있을 이유가 없습니다. **따로 두면 비규격 페이지는 눌렀을 때만 받습니다.**

### 7-왜 이제 되나 — 출처가 같아졌기 때문

전에는 비규격이 `file://`(더블클릭), 앱이 `https://…github.io`라 **출처가 달라 저장함을 못 나눴습니다.**
그래서 "계산을 앱 안으로 옮겨야 한다"고 봤던 것입니다.

**비규격을 같은 깃허브 주소에 올리면 그 전제가 사라집니다.**

```
https://ybnd-yebin.github.io/ybn-inventory/
  ├─ index.html               와이비앤디 앱
  └─ 비규격작업지시서.html      ← 메뉴에서 새 창으로 (2026-09-08 붙임)
        같은 출처 = localStorage 를 나눠 씀
```

덤: `file://`에서 막혀 있던 `ybn-data.js`가 **http에서는 정상으로 붙습니다.**
(모델 주의사항 `asmNoteFor`가 되살아납니다. 홈페이지에서 MODELS 166개·ASSEMBLY 173개 확인)

### 7-⚠ 저장함은 세 가지가 다 같아야 보입니다

**주소(출처) · 브라우저 · 기기** — 셋 중 하나만 달라도 남남입니다. 이게 헷갈리기 쉽습니다.

| 무엇을 잇고 싶은가 | 무엇이 필요한가 |
|---|---|
| 같은 기기 안에서 **앱 ↔ 비규격** | **출처만 같으면 됩니다** ✅ 2026-09-08 됨 |
| **사무실 PC ↔ 현장 폰** (다른 기기) | **구글시트 동기화가 있어야 합니다** ❌ 비규격은 아직 없음 |
| 바탕화면 `file://`에 쌓인 것 → 링크판 | **한 번 내보내고 불러오기** ❌ 단추가 아직 없음 |

`index.html`은 구글 Apps Script로 이미 붙어 있습니다(`autoSync`, `DEFAULT_GS_URL`).
**비규격은 저장함 네 개가 어디에도 안 실립니다** — `nonspec-rows-v1`(납품서) ·
`nonspec-archive-v1`(보관함) · `nonspec-usercolors-v1`(베일 색상) · `nonspec-usercolors-seeded-v1`.

### 7-순서

1. ✅ **문 열기** (2026-09-08 완료) — 홈페이지에 올리고 앱 메뉴에 탭을 붙였습니다.
2. **바탕화면에 쌓인 것 옮기기** ← 다음.
   비규격에 **「자료 통째로 내보내기 / 불러오기」** 단추를 만듭니다(지금은 발주기록 JSON만 됩니다).
   바탕화면판에서 내보내고 링크판에서 불러오면 보관함이 그대로 넘어옵니다. **한 번만 하면 됩니다.**
3. **납품서 한 번 올리기.** 공용 보관함 키 하나에 **파싱 결과가 아니라 원문**을 담습니다
   (PDF에서 뽑은 글자 / 엑셀 행). **두 앱이 각자 제 파서로 읽습니다** — 형식을 공유하지 않으니
   한쪽을 고쳐도 다른 쪽이 안 깨집니다. 이게 핵심입니다.
4. **구글시트 동기화**를 비규격에도. `index`의 `autoSync` 통로를 같이 태웁니다(새로 만들지 않습니다).
   ⚠ **용량 주의** — 아래 「지켜볼 것」의 8칸(360,000자) 한계. 납품서 원문까지 다 태우면 넘칠 수 있어
   **무엇을 태우고 무엇을 안 태울지 골라야 합니다.** (보관함은 태우고, 납품서 원문은 안 태우는 쪽이 유력)
5. ✅ **각자의 일 잇기** (2026-09-16 완료). 비규격 유리 발주 → 앱 발주탭.
   같은 상자를 쓰면서 반쪽만 이어져 있어 **덮여 사라질 수 있었고** 시트에도 안 올라갔습니다.
   이제 비규격은 `[📤 앱 발주탭으로 보내기]` 하나만 두고, 발주서·엑셀·카톡·기록·동기화는
   **앱 한 곳**에서 합니다. **발주서는 색마다 한 장.** 자세한 것은 `CLAUDE.md` 12-11.

### 7-버그 고칠 때

**고칠 때마다 커밋하고 깃허브에 올립니다**(`git push origin main`). 올린 뒤 무엇을 고쳤는지 보고합니다.
올려야 다른 장소에서도 고쳐진 것이 보입니다. 깃허브 Pages 반영에 **1~2분** 걸립니다.
