# 인계 메모 — 출고예시분석 ↔ 바스 재고관리

작성: 2026-07-09
목적: 두 대화방이 서로 모르는 사실을 옮겨, 같은 규칙 위에서 만들기

---

## ⚠️ 먼저: 아직 확정 안 된 것 (제일 중요)

**드림하이텍 예시 ↔ 와이비앤디 예시가 "중복"인지 판정이 안 끝났다.**

- 예빈 님 추정: "중복인 것 같다"
- 근거: `CAIT00450` (B/I 3단 유리도어_브론즈 400L)이 양쪽에 다 뜸. `EO500`도 드림에서 뜸.
- **판정 방법**: 같은 날짜·같은 수량이면 → 중복(한 번만 세야 함).
  날짜나 수량이 다르면 → 각각 실재하는 소요(합산해야 함).
- **판정 전에는 어느 쪽으로도 계산하면 안 됨.** 틀리면 모든 수치가 2배가 되거나 절반이 됨.
- 이 판정은 `0709 한샘 바스` 대화방에서 진행 중.

**→ 결론 나오면 양쪽 앱에 같은 규칙을 넣어야 한다.**

## ✅ 확정된 사실 (양쪽 다 알아야 함)

### 1. 회사 구조

```
생산: 우리(와이비앤디) 한 곳
  ├─ 매출처 와이비앤디 (벤더코드 0000819003)
  └─ 매출처 드림하이텍 (벤더코드 0000812229)
```

- 예빈 님 원문: **"그냥 하나의 회사로 보면 돼. 매출처가 다를 뿐 생산은 우리가 함."**
- 드림하이텍이 따로 만드는 게 아님. 둘 다 우리가 생산.
- **예시표는 업체별로 따로 나온다.** (파일이 2개)

### 2. 벤더 구분

| 벤더 | 코드 | 성격 |
|---|---|---|
| 주식회사 와이비앤디 | `0000819003` | 창고에 넣어두고 그쪽에서 빼감 → 조기경보 대상 |
| 드림하이텍 | `0000812229` | 직납 성격 |

- 엑셀 한 장 안에 두 벤더가 **섞여 있음**. 벤더 컬럼으로 구분 가능.

### 3. 오이도 / 그레이박스 (예시분석 쪽에서 확정)

- **글래스도어**만 두 창고로 나뉘어 운영됨.
- **제품코드가 완전히 동일해서 코드로는 구분 불가.**
- 구분 방법: **파일명에 `(오이도)`** 를 적어주기로 약속. (`filenameIsOido`)
- 납품서 쪽은 `dest` 필드에 `오이도` / `그레이박스`가 찍힘.

> ⚠️ **집계 키에 반드시 창고 구분을 넣어야 한다.**
> `code|shipDate`로 잡으면 나중에 로드된 파일이 앞 창고 물량을 **통째로 덮어씀**.
> 올바른 키: `code | oido(O/G) | shipDate`
> (예시분석 앱에서 이 버그로 오이도 물량이 0이 되는 사고가 있었음. 2026-07-08 수정)

### 4. 날짜 규칙 (예시분석 쪽에서 확정)

- **납품요청일 = 출고일 − 2영업일**
  → 대조 시 `출고일 = 납품요청일 + 2영업일`
  → 달력일 아님. **영업일** 기준.
- 영업일 = 주말 + 한국 공휴일 제외.
- **2026-07-17 제헌절이 18년 만에 공휴일로 재지정됨** (시행 2026-05-11, 금요일이라 대체공휴일 없음).
  → 공휴일 목록에 반드시 포함.
- **오이도는 토요일도 출고함.** 단 토요일 출고분은 금요일에 선발주를 받아 금요일에 작업.
  → 오더발행일 계산 시 토/일 출고분을 **직전 금요일로 당겨 금요일 오더에 합산.**
  → 오이도 외에는 토/일 출고 없음.

### 5. 리드타임 (검증 완료 — 발주일 포함 영업일 수)

`오더발행일 = 출고일 − (리드타임 − 1) 영업일`

| 품목 | 리드타임 | 검증 |
|---|---|---|
| 유로700/500 AL프레임 에어힌지 **비규격** | 7일 | ✅ 발주 7/8 → 출고 7/16 |
| B/I 슬림파우더장 거울도어 | 3일 | ✅ 발주 7/8 → 출고 7/10 |
| B/I 현관 오픈장 브론즈 거울 | 3일 | ✅ 발주 7/8 → 출고 7/10 |
| 유리장식벽장 · AL도어 · 키큰장 · 유로700 정규격 | 5일 | ✅ 발주 7/8 → 출고 7/14 |
| 글래스도어 정규 | 2일 | ❓ 미검증 |
| (비)글래스 채널도어 | 5일 | ❓ 미검증 |
| 빗각 / 빗면 | 7일 | ❓ 미검증 |
| KB 미러장식 | 7일 | ❓ 미검증 |
| 그 외 정규격 (기본값) | 5일 | ❓ 미검증 |

> 오더예상일이 주말/공휴일이면 **직전 영업일로 당김.**

### 6. 발주 패턴 (바스 쪽에서 발견 — 예시분석도 알아야 함)

- 거래처는 예시에 찍힌 소요량만큼 **조금씩 소진**하다가, 쌓이면 **뭉텅이로 발주**함.
- 실제 예: `EURO5 베일화이트` 납품서 40장 / 50장 ↔ 예시표 전체 예정 12장 / 7장.
  **자릿수가 다름.**
- 그래서 예시 수량과 납품 수량을 1:1로 비교하면 안 됨. 발주점 역산이 필요.

> 💡 **이 사실이 예시분석의 "헛스윙 분석"에 영향을 준다.**
> 예시에 뜬 게 그날 안 나왔다고 곧바로 "헛스윙"이 아닐 수 있음.
> 나중에 뭉텅이로 나올 수 있음 → **"지연 적중"과 "진짜 헛스윙"을 구분해야 함.**

## 📤 예시분석 → 바스 재고관리 (넘길 것)

1. **오이도/그레이박스 키 충돌 버그.** 같은 코드를 쓰는 항목이 있으면 집계 키에 구분자를 넣을 것.
2. **날짜 환산 규칙.** 납품요청일 +2영업일 = 출고일. 영업일 기준.
3. **2026-07-17 제헌절** 공휴일 목록에 추가.
4. **검증된 리드타임 4종** (위 표의 ✅ 항목).
5. **오이도 토요일 출고 규칙.**

## 📥 바스 재고관리 → 예시분석 (받을 것)

1. **드림하이텍 / 와이비앤디 벤더 구분.** 예시분석 앱은 지금 이 개념이 아예 없음.
   → 벤더 컬럼(`0000812229` / `0000819003`)을 파싱해서 분류에 추가해야 함.
2. **중복 판정 결과.** (아직 안 나옴 — 나오면 즉시 반영)
3. **뭉텅이 발주 패턴.** 헛스윙 분석 로직에 "지연 적중" 개념 추가 필요.
4. **`CAIT00450` 같은 양쪽 등장 코드 목록.**
