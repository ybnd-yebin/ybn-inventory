# 라벨마킹 — 인계 문서

한샘 출고라벨 PDF(Crystal Report)를 열면 규칙에 따라 형광펜·메모를 자동으로 얹고, 원본 라벨 그대로 인쇄하는 단일 HTML 앱.
현재 파일: `라벨마킹.html` (단일 파일, 라이트 모드)

작업자(예빈)는 코드를 읽지 않음. 수정은 항상 **완성된 전체 파일**로 전달할 것.

> **2026-10-02 — 홈페이지에 올렸습니다.** 앱 메뉴 `🏷 라벨마킹 ↗` 에서 새 창으로 열립니다
> (`https://ybnd-yebin.github.io/ybn-inventory/라벨마킹.html`). 비규격 작업지시서와 같은 방식입니다.
> - **앱 탭으로 합치지 않습니다** — 라벨은 A4 가로·여백 0, 앱은 A4 세로·여백 10mm 라 `@page` 가 부딪칩니다.
> - 앞으로도 계속 고칩니다. **고친 뒤에는 이 파일도 푸시**해야 홈페이지에 반영됩니다(CLAUDE.md 9-2·자동 푸시).
> - ⚠ **설정은 주소마다 따로 저장됩니다.** 더블클릭으로 열던 판에 저장된 형광펜 규칙·색은
>   홈페이지 판에 안 따라옵니다 → 옛 판에서 「저장 파일 내보내기」 후 새 판에서 불러오십시오.

## 0. 현장에서 이 라벨이 어떻게 쓰이나 (2026-09-22, 사장님 설명)

이걸 모르면 자리 잡는 규칙이 다 틀립니다.

1. 인쇄 → 형광펜으로 색·모델·특이사항 구분 → 십자로 잘라 모델별로 나눠 **호치케스로 찝어** 작업자에게 줌
2. 작업자가 그 모델을 만들면서 **라벨을 제품에 스카치테이프로 붙임**
3. 포장 담당이 박스에 담고 **그 라벨을 박스 겉에 붙임**

```
      ┌───────────────────────────┬────┐
      │                           │    │
      │  이 큰 조각이 제품 → 박스   │쪼가│  ← 세로 바코드 쪽. 남습니다
      │  → **형광펜만** 남깁니다     │ 리 │  → **메모는 전부 여기에**
      │                           │    │
      └───────────────────────────┴────┘
                                  ↑
                        라벨지가 **이미 갈라져 있는 선**
```

- **가운데 십자선**만 칼로 자릅니다.
- **세로 바코드 왼쪽 선은 라벨지가 이미 갈라져 있습니다.** 손으로 뜯으면 떨어집니다.
- 큰 조각이 제품·박스에 붙으므로 **거기에는 형광펜 말고 아무것도 얹지 않습니다.**
  ⚠ 한때 묶음 수량·유리 사이즈를 라벨 왼쪽 위에 적었다가 이 규칙에 걸렸습니다. 되돌리지 마십시오.
- **잉크를 아낍니다.** 같은 말을 여러 장에 되풀이해 찍지 않습니다.

## 1. 동작 구조

- **pdf.js 3.11.174** (cdnjs) 로 PDF를 읽어 페이지마다 canvas에 그림
- canvas 위에 투명 overlay를 겹쳐 형광펜(div, `mix-blend-mode:multiply`)과 메모를 올림 → 원본 바코드·글자는 손대지 않음
- 좌표는 전부 **페이지 대비 비율(0~1)** 로 저장
- 세로(회전) 글자는 판정에서 제외 (transform의 b, c 값이 0이 아니면 건너뜀)

### 라벨지 규격 (PDF 실측)
- A4 가로 841 × 595pt, **한 장에 4면** (2열 × 2행), 가운데 **가로 절취선**, 인쇄 후 **십자(+)로 절단**
- 면 번호: 좌상 1 / 우상 2 / 좌하 3 / 우하 4
- 사분면 경계: x 0.5, y 0.5
- 세로 바코드 위치: 왼쪽 칸 x 388~405pt / 오른쪽 칸 x 812~829pt
- 세로 요소 시작 y: 윗줄 61pt / 아랫줄 330pt
- 라벨 한 장에 품명이 **두 번** 찍힘 (큰 칸 + 작은 칸)
- **표(큰 칸) 오른쪽 끝 = 갈라진 선**: 왼쪽 칸 x 349.5pt(0.4156) / 오른쪽 칸 773pt(0.9192).
  그 오른쪽이 「쪼가리」이고 세로 바코드·세로 글자가 거기 있습니다.

### PDF 글자 조각의 함정 (중요)
1. 한 줄이 여러 조각으로 쪼개져 들어옴. 예: `비규격` 과 `(536*0*356*0 M)` 이 별개 조각
   → `buildLines()` 에서 붙어 있는 조각을 한 줄로 이어 판정 (간격 < 0.007, 글자 높이 비슷할 때만)
2. 조각 사이 공백은 어느 조각에도 속하지 않아 형광펜이 끊김
   → `rectsFor()` 에서 같은 줄의 인접 사각형을 이어 붙임 (간격 < 0.012)
3. 큰 칸 품명은 두 줄로 잘림. 예: `… OB M ` / `비규격(410*0*736*0 M)`
   → `mergeWrapped()` 에서 같은 x, 바로 아랫줄이면 한 덩어리로 이음 (첫 줄에 `Euro###` 또는 `AL도어` 가 있을 때만)
4. 오더번호는 `03128` 과 `72516` 이 글자 크기가 달라 별개 조각 → 5자리 숫자만 보고 사이즈로 판단하면 안 됨
5. 품목코드(`ME1BD0077`)는 품명과 다른 칸 → 품명 줄에 붙어 있다고 가정하면 안 됨

## 2. 라벨 품명 형식

```
Euro700 Grace W/Cotton OB BD2R 9091 M
Euro700 Grace ETP HD BC1A 4291 L
Euro700 Veil BRZ OB WRMB 6135 M
Euro700 Veil Shade OB M 4065 M
(P)Euro500 PG/RG CH M 3573(공용) M
(P)Euro500 PG/Off WH CH BNDB2N 2091 M
Euro700 Grace ETP OB WRMB 비규격(536*0*356*0 M)
유리장식벽장 AL도어 비규격(500*0*814*0 R)
유리장식키큰장 AL도어 60222 M
```

구조: `[제품군] [시리즈] [색상] [손잡이타입] [모델코드] [사이즈] [끝문자]`
- 손잡이 타입: `OB`, `HD` (Euro700) / `CH` (Euro500)
- 사이즈 끝 두 자리가 `73` 이면 높이 736 공용 사이즈 (2073, 2573 … 6073)
- 끝문자 `M` / `L` / `R`

## 3. 표시 규칙

### 색상 (제품 색)
정규식: `/((?:\(P\))?Euro\d{3}\s+(?:(?:Grace|Veil)\s+)?(.+?))\s+(?:OB|HD|CH)(?:[\s]|$)/`
칠하는 범위는 **제품군부터 색상까지** (예: `Euro700 Grace ETP` 전체)

끝을 `(?:\s|$)` 로 둔 것은 AS 라벨의 「내용참조」 줄 때문입니다 — 칸 너비에 잘려
손잡이 타입(`… W/Cotton HD`)에서 끝나는 줄이 있어, 공백만 요구하면 색상을 못 찾습니다.
(2026-09-22 수정. 그전에는 그 줄에 색이 안 칠해졌습니다)

| 코드 | 이름 | 형광펜 |
|---|---|---|
| `W/Cotton` | 웜코튼 | 안 칠함 |
| `PG/Off WH` | 화이트 (Euro500) | 안 칠함 |
| `ETP` | 에토프 | 주황 `#ffb25c` |
| `PG/RG` | 로즈골드 (Euro500) | 주황 `#ffb25c` |
| `BRZ` | 브리즈 (Veil) | 회색 `#c2c6ca` |
| `Shade` | 쉐이드 (Veil) | 초록 `#8ce08f` |
| (미확인) | 아보카도 (Euro500) | 초록 예정 — 라벨 코드 아직 못 봄 |

PDF를 열면 새 색상 코드가 사이드바 목록에 자동으로 뜨고, 클릭으로 색 지정 + 한글 이름 입력 가능. 브라우저에 저장됨.

### 형광펜·메모 규칙 (기본값)

| 규칙 | 대상 | 표시 | 메모 |
|---|---|---|---|
| 모델명 | `HD` 는 포함해서, `OB`·`CH` 는 빼고 그 뒤부터 모델명 끝(M/L/R)까지. 뒤에 붙은 치수코드(`427X0X910X0`)는 제외 | 노랑 `#fff02e` | — |
| AL도어 **비규격만** | `AL도어` 뒤의 `비규격(…)` 만. **정규격(`유리장식키큰장 AL도어 45222 M`)은 안 칠함** — 규격이 정해진 물건이라 형광펜이 필요 없음 (사용자 확정 2026-09-22) | 노랑 | — |
| AS 내용참조 줄 | 품명에 `(Euro` 가 있으면 그 줄 전체. AS 대표코드 라벨(`KITAS0075 AS용 대표…`)은 진짜 모델명이 「내용참조」 줄의 `MBD2R상마이다_895*380(Euro700 Grace W/Cotton HD` 에 있음. 정상 품명은 `(P)Euro500` 이라 `(Euro` 로 걸리지 않음 | 노랑 + 색상 | — |
| A/S 건 | 참조문서번호 `54`로 시작하는 10자리 | 연노랑 `#fff66b` | AS |
| 피스 동봉 | `WRMB`, `WF`, `WFED` (단 `WFMD` 는 아님) | 없음 | 피스 |
| 목대 1개 | `BLD1R`, `BLD1UA`, `BRO1R` | 없음 | 목대1 |
| 목대 2개 | `BLD2R` | 없음 | 목대2 |
| 115도 힌지 | `BC1A`, `BC1B` | 없음 | 115° |
| 155도 힌지 | `TCPID` | 없음 | 155° |
| HD | 뒤에 모델명이 따라오는 `HD` 만 (내용참조 문구 끝의 HD 는 제외) | **없음** (2026-09-22) | HD |
| L / R | 품명 끝의 L 또는 R | 없음 | 찾은 글자 그대로 (`$0`) |

**모델명 예외 (NO73)**: 사이즈가 `…73` 이면 칠하지 않음. 줄바꿈으로 잘려 한 글자만 남은 조각(`M `)도 칠하지 않음.
정규식: `/(?<!\d)\d{2,3}73(?!\d)|^\S{0,1}\s*$/` — `비규격(378*0*736*0 M)` 의 736은 걸리지 않음 (4자리 연속 숫자가 아니므로)

**오더번호·품목코드는 절대 칠하지 않음.**

### ⚠ 칸에 잘린 품명 — 형광펜이 칸 선을 넘지 않게 (2026-09-22)

품명이 칸보다 길면 라벨에는 `… 비규격(450*0*880*` 까지만 보입니다.
그런데 **pdf.js 는 잘리기 전 글자 전체**(`…880*0 M)`)를 줍니다. 그대로 칠하면
안 보이는 부분까지 노랗게 칠해져 **칸 선을 넘어 옆 칸을 침범합니다**
(사장님 2026-09-22 "박스 밖으로 선을 넘었는데 불필요할거같아요").

**답은 PDF 안에 있습니다.** 크리스탈리포트는 글자를 자를 때 **그 칸만큼 clip 을 겁니다.**
`clipRects()` 가 `getOperatorList()` 에서 그 네모를 읽고, `clipRightOf()` 가 글자마다
제 칸을 찾아 줍니다. **안 잘리는 칸에는 clip 이 없으니 아무 영향도 없습니다.**

`buildLines()` 가 글자마다 `rightLimit` 를 정하고 `rectsFor()` 가 거기서 자릅니다.
한계는 셋 중 가장 왼쪽:

| | |
|---|---|
| ① PDF 의 clip 오른쪽 끝 | 가장 정확합니다 |
| ② 같은 줄 바로 오른쪽 글자 | clip 이 없을 때의 대비 (예: `1 / 1`) |
| ③ 세로 글자가 시작되는 자리 −0.004 | 거기부터는 쪼가리라 가로 글자가 올 수 없습니다 |

- ⚠ **칸 너비를 숫자로 적어 두지 마십시오.** 서식이 바뀌면 조용히 틀립니다.
- ⚠ clip 을 고를 때 **글자 시작점이 그 칸 안**이어야 합니다. `o.x > c.x1` 로만 거르면
  옆 칸 clip 의 오른쪽 끝에 딱 붙어 시작하는 글자를 제 칸으로 잘못 봅니다 —
  작은 `03129` 의 칸이 큰 `03500` 을 자르는 일이 있었습니다.
- 매칭한 글자의 **앞뒤 공백도 뺍니다** — 칸을 채우려 붙은 공백까지 칠하면 역시 선을 넘습니다.
- 검증(2026-09-22):
  - `CrystalReportViewer (43) 라벨지.pdf` — 잘린 품명이 없어 **형광펜 82곳 그대로**(총면적도 같음).
  - `CrystalReportViewer (43)바코드.pdf` (사장님이 지적하신 그 라벨) — 잘린 품명 **5곳**을 찾아
    **3.0~6.1mm 씩 덜 칠합니다.** `(450*0*880*0 M)` · `(600*0*880*0 M)` 등.

### 동그라미 — 기본값은 꺼 둡니다 (2026-09-22)
붙는 쪽에는 **형광펜만** 남깁니다. HD 빨간 동그라미는 규칙 `r5` 의 표시를 「표시 없음」으로 두었습니다.
HD 정보는 잃지 않습니다 — **노랑 형광펜이 `HD` 부터 시작**하고(MODEL_RE 가 HD 를 포함),
쪼가리에도 「HD」 메모가 갑니다. 되살리려면 규칙 편집기에서 표시를 「동그라미」로 바꾸면 됩니다.
- (그릴 때) 선 두께 2.3px, 글자 대비 가로 1.45배 / 세로 1.55배

### 형광펜 진하기
`.mark { opacity: var(--hl-op) }` 한 곳입니다. 사이드바 슬라이더 20~100%, 기본 **55%**,
`label-mark-hlop-v1` 에 저장. `mix-blend-mode:multiply` 라 **검은 글자는 진하기와 상관없이 그대로 검게**
남고 바탕 색만 옅어집니다 — 그래서 옅게 할수록 밑의 글자가 또렷해집니다.

### 규칙 편집기 기능
- 포함 / 칠할 곳 / 예외 / 메모 / 표시(형광펜·동그라미·표시 없음) / 색
- 칠할 곳을 `/…/` 로 감싸면 정규식, `*` 는 줄 전체, 비우면 메모만
- 예외도 `/…/` 로 감싸면 정규식 (쉼표 포함 정규식 때문에 통째로 판정)
- 메모에 `$0` 을 쓰면 찾은 글자가 들어감

## 4. 메모 위치 — 전부 「쪼가리」 안에 (2026-09-22 전면 개정)

**메모는 갈라진 선 오른쪽 쪼가리에만 적습니다.** 왼쪽 큰 조각은 제품·박스에 붙으므로
형광펜 말고는 아무것도 얹지 않습니다 (0번 참고).

### 약속 표시 (사장님 2026-09-22 — "자리가 좁아서 서로 알게끔 표시만 하면 된다")

자리가 좁으니 **말을 길게 적지 않습니다.** 길게 적으면 글자 크기가 자동으로 작아져
오히려 안 읽힙니다. 아래 표가 약속입니다. **바꾸려면 규칙 편집기의 「메모」 칸만 고치면 됩니다.**

| 표시 | 뜻 | 어디에 |
|---|---|---|
| `3장` | 품명이 같은 것이 3장 — **묶음마다 첫 장에만** | 위쪽 가로 |
| `421×708` | 유리 사이즈 (수납도어류 비규격) | **세로 칸** |
| `피스` | 피스 동봉 | 위쪽 가로 |
| `목대1` · `목대2` | 목대 1개 · 2개 | 위쪽 가로 |
| `115°` · `155°` | 힌지 각도 | 위쪽 가로 |
| `HD` | HD 손잡이 | 위쪽 가로 |
| `L` · `R` | 좌 · 우 | 위쪽 가로 |
| `AS` | A/S 건 | 위쪽 가로 |
| `유리?` | 계통을 못 가려 유리 사이즈를 못 냄 — **확인 필요** | 세로 칸 |

- 가로 메모가 여럿이면 한 줄에 `·` 로 잇습니다. 예: `2장 · R`
- **유리 사이즈에 「유리」를 안 붙입니다.** 쪼가리에서 `×` 로 이어진 숫자는 이것뿐이고,
  라벨 본문의 장규격은 대문자 `X`(`450X0X736X0`) 라 헷갈리지 않습니다.

쪼가리에서 쓸 수 있는 자리는 **세로 바코드·세로 글자가 시작되기 전 윗부분**뿐이고,
**아주 좁습니다.**

| | 가로 (왼쪽 칸 / 오른쪽 칸) | 세로 (여유 뺀 뒤) |
|---|---|---|
| 윗줄 라벨 (1·2면) | 17.8mm / 14.4mm | 15.9mm |
| 아랫줄 라벨 (3·4면) | 17.8mm / 14.4mm | **8.5mm** — 절취선과 세로 바코드 사이 |

### 유리 사이즈는 **세로로** 적습니다 (사장님 확정 2026-09-22)

사장님이 라벨에 직접 그려 보여 주신 방식입니다. 쪼가리의 세로 글자들 **사이**가 비어 있어,
거기에 세로로 적으면 **길이를 라벨 높이만큼** 쓸 수 있습니다.

```
        │세로 글자들│                     │
        │ 날 품 │유│ 납 바              │
        │ 짜 명 │리│ 품 코              │   ← 유리 사이즈를 품명 세로줄과
        │    │사│ 처 드              │      납품처 세로줄 **사이**에
        │    │이│                    │
        │    │즈│                    │
```

| | 빈 칸 너비 |
|---|---|
| 품명 세로줄 ↔ 납품처 세로줄 사이 | **5.17mm** ← 여기를 씁니다 |
| 바코드 뒤 ~ 절취선 앞 | 3.43mm |
| 품명 세로줄이 두 줄일 때 | 1.73mm — 세로로 못 적습니다 |

- `stripColumns()` 가 **라벨마다** 세로 글자들의 x 를 훑어 **가장 넓은 빈 칸**을 찾습니다.
- 품명이 길면 세로줄이 두 줄이 되어 그 칸이 사라집니다 (`AL프레임 에어힌지 벽장유리도어 18T` ·
  `3073(공용) M` 등). 그때는 세로로 적지 않고 **위쪽 가로 줄로 되돌립니다.**

#### ⚠ 왼쪽 칸과 오른쪽 칸이 **똑같이 판단해야 합니다** (2026-09-23)

사장님 지적: **"이거 왜 짝짝이야?"** — 같은 물건 넉 장인데 **왼쪽 둘만 세로, 오른쪽 둘은 가로**로 나왔습니다.

까닭은 오른쪽 한계가 서로 달랐기 때문입니다.

| | 오른쪽 한계 | 세로 글자 왼쪽 끝부터 |
|---|---|---|
| 왼쪽 라벨 | 0.4980 (세로 절취선 앞) | 0.0674 |
| 오른쪽 라벨 | 0.9885 (용지 끝 3.4mm 앞) | **0.0543** |

품명이 길어 **바코드 뒤 좁은 틈**(3.0mm)밖에 안 남았을 때, 왼쪽은 그 틈이 한계 안이라
세로로 적고 오른쪽은 한계를 넘어 가로로 보냈습니다.

→ 이제 빈 칸을 **라벨 기준(세로 글자 왼쪽 끝부터)** 으로 재고, 오른쪽 한계는 **둘 중 좁은 쪽**을 씁니다.
**넉 장이 늘 같은 모양**으로 나옵니다.

#### 좁은 칸에는 세로로 안 적습니다 — `GLASS_MIN_MM = 4.6`

사장님 2026-09-23: **"가로로 되어있는 글씨크기가 맘에드는데 … 위치도 괜찮은거같아."**

세로 칸이 좁으면 글자가 9~10px 까지 작아집니다. **가로 줄은 15px** 이라 그쪽이 훨씬 잘 읽힙니다.
그래서 **13px 이 들어가는 너비(4.6mm = 13×1.15 + 양옆 0.3mm)** 를 밑선으로 두고,
그보다 좁으면 세로를 포기하고 **가로 줄로 크게** 적습니다.
⚠ 예전 값 2.6mm 로 되돌리지 마십시오 — 바코드 뒤 3.0mm 틈에 작게 적히던 값입니다.

실측(2026-09-23):

| 품명 | 빈 칸 | 넉 장 모두 |
|---|---|---|
| 짧음 (유리장식벽장 등) | **5.17mm** | 세로 15px |
| 긺 (AL프레임 에어힌지) | **1.73mm** | 가로 15px |
- 글자 방향은 라벨의 다른 세로 글자와 같습니다(아래에서 위로). CSS 는
  `.note.vert{transform:rotate(-90deg);transform-origin:0 0}` — 기준점이 **글자 왼쪽 아래 모서리**라,
  코드에서 `y` 에 글자 길이를 더해 넣습니다. 위 끝은 다른 세로 글자와 나란히 맞춥니다.
- 크기는 칸 너비에 맞춰 `GLASS_FS = [16…13]` 중에서 고르고, **양옆 0.3mm 는 띄웁니다.**
  딱 맞추면 인쇄가 조금만 밀려도 옆 세로줄에 닿습니다 (16px 로 뒀다가 0.15mm 밖에 안 남아 15px 로 내렸습니다).
- 덕분에 위쪽 가로 띠가 헐거워져 **가로 메모도 전부 15px** 이 됐습니다.

#### ⚠ 빈 자리는 **라벨 하나하나 따로** 잽니다

`stripBoxes()` 는 사분면을 뭉뚱그리지 않고 **쪽·사분면마다** 잽니다.
세로로 적히는 품명이 길면 그 칸만 위로 더 올라오기 때문입니다.

실제로 이 라벨지에서 아랫줄 라벨의 세로 글자는 **31칸이 11.50mm**, `BNDC2N 3091 M` **한 칸만 9.15mm**
였습니다. 그 하나를 전체에 적용하는 바람에 **모든 아랫줄 라벨이 2.3mm 씩 손해**를 봤고,
그만큼 글자가 작아졌습니다. (2026-09-22 수정)

#### 메모는 띠의 **아래쪽**에 붙입니다 — 세로 바코드 바로 위

(사장님 2026-09-22 "가끔 인쇄할때 밀려서 내려오기도하고 반대로 되기도 …
아래쪽에 있는 메모는 좀 더 내리는게 안정적")

- 위에 붙이면 윗줄 라벨은 **용지 가장자리**에, 아랫줄 라벨은 **가로 절취선**에 바짝 붙습니다.
  둘 다 인쇄가 밀리면 잘려 나가는 자리입니다.
- 절취선은 종이가 **실제로 갈라지는 자리**라 걸치면 글자가 반으로 찢어집니다.
  세로 바코드에 가까워지는 것보다 훨씬 나쁘므로 그쪽에 여유를 몰아줍니다.
- 덤으로 네 라벨의 메모가 모두 **세로 바코드 바로 위**라는 같은 자리에 옵니다.
- 코드: `layoutStripNotes()` 의 `top = Math.max(box.y0*pxH, box.y1*pxH - blockH)`.
  ⚠ `box.y0` 부터 아래로 쌓는 예전 방식으로 되돌리지 마십시오.
- ⚠ **`cut`(절취선 여유, 2.5mm)은 '바닥'이 아니라 '천장'입니다.** 아래쪽에 붙이므로 실제 거리는
  이보다 큽니다. 이 값은 "글자 덩어리가 이보다 높이 올라오면 안 된다"는 뜻이라,
  크게 잡으면 **자리는 그대로인데 글자만 작아집니다.** 2.2 → 1.5 → 2.5 로 손대 보고 2.5 로 두었습니다.

#### 자리와 글자 크기

- **숫자로 적어 두지 않고 `stripBoxes()` 가 매번 PDF 에서 잽니다.**
  세로(회전) 글자의 x·y 가 쪼가리의 빈 칸을 정합니다. 그래서 `openPdf` 가 세로 글자도
  `page.vert` 에 모아 둡니다(형광펜 판정에서는 여전히 제외).
- **메모의 왼쪽 끝은 세로 글자의 왼쪽 끝(`colX`)에 맞춥니다.** 예전에는 거기서 1mm 더 왼쪽이라
  갈라진 선에 바짝 붙었습니다 (사장님 2026-09-22 "살짝 오른쪽으로 이동해줘").
  지금은 갈라진 선에서 **2.91mm** 오른쪽입니다.
- 물러서는 여유: 세로 바코드에서 0.5mm · **용지 위 가장자리에서 6mm** · 가로 절취선에서 2.5mm.
  ⚠ 용지 위 6mm 는 메모가 **세 줄까지 늘어날 때만** 닿는 자리입니다. 원본 라벨의 맨 위 잉크가
  15.9mm 라 그보다 위는 이 프린터에서 찍어 본 적이 없습니다 — 더 올리지 마십시오.
- **글자 크기는 자동입니다.** `STRIP_FS = [15,14,13,12,11,10,9]` 중 **다 들어가는 가장 큰 것**.
  줄 간격은 `STRIP_LH = 1.25`.
  너비는 어림하지 말고 캔버스 `measureText` 로 **실제로 잽니다** (한글·숫자·`·` 가 섞여 어림이 잘 틀림).
- **글자를 줄여 한 줄에 몰아넣기보다 줄을 나눕니다.** 큰 크기부터 내려오면서 줄을 나눠 재기 때문에,
  줄이 늘더라도 큰 글자가 먼저 걸립니다.
  ⚠ 한때 `2장 · 421×708 · R` 을 한 줄로 욱여넣다가 **9px 까지** 작아진 적이 있습니다
  (사장님 2026-09-22 "글씨가 너무 작아졌어. 줄바꿈으로 해줘").

- **끊는 자리를 전부 따져 봅니다** (`splitCandidates`). 붙일 자리마다 붙이거나 마는
  모든 경우를 만들어(셋이면 4가지), 자리에 들어가는 것 중
  **① 줄이 가장 많은 것 → ② 줄 수가 같으면 가장 고른 것**을 고릅니다.
  ⚠ 앞에서부터 욱여넣는 방식(greedy)만 쓰면 `2장 · HD` / `R` 처럼 **어중간하게 갈립니다**
    (사장님 2026-09-22 "2장 / HD R 로 하든, 3줄은 어렵나"). 지금 나오는 모양:

  | 내용 | 윗줄 라벨 | 아랫줄 라벨(자리가 좁음) |
  |---|---|---|
  | `2장` `HD` `R` | `2장` / `HD` / `R` — 15px 세 줄 | `2장` / `HD · R` — 12px 두 줄 |
  | `2장` `R` | `2장` / `R` — 15px | `2장 · R` — 15px 한 줄 |
  | 네 가지 | `2장` / `목대2` / `115° · R` — 15px | `2장 · 목대2` / `115° · R` — 11px |
- 줄 차례: **묶음 수량 → 유리 사이즈 → 규칙 메모**(피스 → 목대 → 힌지 → HD → L/R).
- 글자는 **왼쪽 정렬**, 빨강 굵게. 세로쓰기는 하지 않습니다.
- 켜고 끄기는 사이드바 「라벨에 더 적기」. `label-mark-extras-v1` 에 저장됩니다.
- ⚠ **`STRIP_X1` 의 오른쪽 한계**: 왼쪽 칸 0.4980(세로 절취선 앞) / 오른쪽 칸 0.9885(용지 끝에서 3.4mm).
  오른쪽 칸이 좁아 같은 글자라도 한 단계 작은 크기가 나올 수 있습니다 — 정상입니다.

**붙는 쪽 침범 0 · 절취선 넘김 0 · 인쇄된 글자와 겹침 0**

| 잰 것 | 처음 | 아래쪽 정렬 | 라벨별로 재기 | **유리를 세로로** |

절취선·용지 가장자리에서도 훨씬 멀어졌습니다.

### 자동 메모는 편집·이동 불가
예전에 자동 메모를 클릭해 건드리면 "직접 쓴 메모"로 저장돼서 다음 실행 때 중복으로 쌓이는 버그가 있었음.
→ 자동 메모는 `contenteditable=false`, 이동 핸들 없음.
→ PDF 열 때 같은 사분면·같은 글자로 저장된 메모는 자동 삭제(`cleanupDuplicateNotes`).
메모 도구로 직접 찍은 메모만 편집·이동 가능.

## 5. 프레임 수량 탭

1차 프레임 조립 담당은 **색 구분 없이 모델·사이즈로만** 수량을 봄.
에토프 4073 5개 + 웜코튼 4073 5개 → `M 4073(공용) M` 10개.

- 집계 키: `OB`/`HD`/`CH` 뒤부터 끝까지 (치수코드 제외). AL도어 제품은 제품명 포함 전체
- **라벨 한 장 = 한 개.** `1/2`, `2/2` 는 수량 2 (각각 1개씩 셈)
- 한 장에 품명이 두 번 찍히므로 **사분면마다 가장 온전한(긴) 줄 하나만** 셈
- A/S 대표코드(`KITAS0075 AS용 …`)는 제외
- 표: 모델·사이즈 가운데 정렬, 수량 왼쪽 정렬, 표 폭 560px
- 인쇄 시 **A4 세로** 한 장 (`@page framePage`)

검증: 8/26 PDF 12페이지 → 라벨 48장 전부 집계, `M 3565 M` 4개 (주문 2건 × 1/2·2/2) 맞음.

## 6. 인쇄

- 라벨 탭: `@page { size: A4 landscape; margin: 0 }`
- 한 장의 크기는 **`--sheet-w` × `--sheet-h`** 한 곳에서 나옵니다. `setSheetSize()` 가
  **PDF 에서 재서** 넣습니다 — 포인트를 밀리미터로 바꾸고(×25.4/72), A4 가로보다 0.2mm 작게
  **같은 비율로** 줄입니다. 이 라벨지(841×595pt)는 **296.54 × 209.80mm** 가 됩니다.
  캔버스는 `width:100%; height:100%` 로 그 상자를 꽉 채웁니다. 비율이 PDF 와 같아 안 찌그러집니다.

  **왜 이렇게 바꿨나 (2026-09-22)** — 그 전에는 `height:calc(100vh - 2px)` · `width:fit-content` 였습니다.
  | 증상 | 까닭 |
  |---|---|
  | 쪽수가 늘어남 | `100vh` 가 인쇄 창의 여백·배율 설정에 따라 달라져, 한 장이 용지보다 커지면 두 장으로 쪼개짐 |
  | 형광펜 자리가 밀림 | `fit-content` 로 잡힌 상자 폭이 캔버스 폭과 미세하게 어긋남. 형광펜은 **상자** 기준 %, 글자는 **캔버스** 기준이라 둘이 어긋나면 색이 밀림 |

  고친 뒤 실측(2026-09-22): 상자·캔버스·오버레이 세 상자가 **소수점까지 같고**(1119.719 × 792.188px),
  8장 모두 높이가 같습니다.
  - ⚠️ `100vh` 나 `fit-content` 로 되돌리지 마십시오. 옛 인계문서의 "고정 mm 금지"는
    **용지 크기(210mm)를 그대로 쓴 것**이 문제였습니다. 지금은 용지보다 작게, PDF 비율대로 잡습니다.
  - ⚠️ `.pagewrap{line-height:0; font-size:0}` 도 함께 있어야 합니다. 안 두면 캔버스 아래에
    글줄 여백이 붙어 한 장이 용지보다 커집니다(빈 장이 낌).
- 인쇄 버튼 누르면 **먼저 모든 캔버스를 검사**(각 페이지 25%/50%/75% 가로줄 샘플링) → 빈 페이지 있으면 `state.pdfDoc` 으로 다시 그림 → 그래도 비면 인쇄 막고 알림
  - 이유: 43장이면 캔버스가 약 300MB. 메모리 부족 시 브라우저가 내용을 조용히 버림
- 인쇄 창 권장 설정: **여백 없음, 배율 실제 크기(100%)**
- **바로 인쇄합니다. PDF 로 저장했다가 인쇄하지 않습니다** (사장님 2026-09-22
  "이걸 저장해놓을 이유가 없거든 … 또 라벨마킹하고 저장하면 그거 관리가 안될거같은데").
  예전 권장 순서였던 「PDF 로 저장 → 그 PDF 를 인쇄」는 100vh 시절 쪽수가 터지던 것을

## 8-1. 유리 사이즈 (2026-09-22 확정)

라벨의 `비규격(450*0*736*0 L)` 숫자는 **장규격(납품 사이즈)** 입니다 (사용자 확정).
같은 PDF 안에 `M 3073(공용)` 과 `비규격(325*0*736*0 M)` 이 나란히 있어 736 이 납품 세로와 맞습니다.

유리 차감은 계통마다 다릅니다. **정본은 `CLAUDE.md` 12-1** 이고, 아래는 장 → 프레임 → 유리를
한 번에 접은 값입니다. 숫자를 두 곳에 두지 않으려고 접었을 뿐이니, **고칠 때는 12-1 을 보십시오.**

| 계통 | 유리 = 장 − | 판별 |
|---|---|---|
| KB AL프레임 에어힌지 | W −46, H −44 | `에어힌지` · `AL프레임` |
| KB 빗면 프레임 | W −100, H −14 | `빗각` · `빗면` |
| 시그니처 글래스도어 | W −9, H −5 | `글래스도어` |
| EURO 유리장식장 | **W −29, H −28** | `유리장식` · `장식장` · `키큰장` · `벽장` |

- ⚠ **판별 순서가 중요합니다.** 에어힌지·빗면을 유리장식보다 **먼저** 봐야 합니다.
  이름에 '키큰장'·'벽장'이 겹쳐, 뒤에 두면 유리장식으로 잘못 흡수됩니다 (CLAUDE.md 6-3 과 같은 함정).
- ⚠ **유로 계열은 적지 않습니다.** 유리 세로 감산이 손잡이 개수(양면 −3 / 단일 −1)로 갈리는데
  라벨에 그 정보가 없습니다. 지어내지 않습니다.
- **정규격은 적지 않습니다** (사이즈가 `비규격(…)` 꼴일 때만).
- 계통을 못 가리면 숫자를 지어내지 말고 **`유리?`** 로 적습니다 — 확인 필요라는 뜻입니다.
- 검증(2026-09-22): `600*2255` → 571×2227 · `450*736` → 421×708 · `500*864` → 471×836.

## 8-2. 묶음 수량 (2026-09-22 확정)

**품명 전체가 같은 라벨끼리 한 묶음**입니다 (사장님 확정). 색·손잡이·모델·사이즈·L/R 이 모두 같아야 합니다.

- **묶음마다 첫 장 하나에만** `3장` 처럼 수량만 적습니다.
  어차피 모아서 호치케스로 찝고 **맨 위 장에만 수량이 있으면 되며**, 다 적으면 잉크가 아깝습니다
  (사장님 2026-09-22). `applyBundleNotes()` 의 `done` 집합이 그 역할입니다.
  ⚠ 한때 모든 장에 `3장 묶음` 을 적었습니다. 되돌리지 마십시오.
- **한 장뿐이면 안 적습니다.**
- 라벨 한 장 = 한 개. 한 장에 품명이 두 번 찍히므로 사분면마다 가장 온전한 줄 하나만 셉니다.
- AS 대표코드 라벨과 그 「내용참조」 줄은 품명이 아니므로 세지 않습니다.
- ⚠ `L` 과 `R` 은 **다른 묶음**입니다. `…(450*0*736*0 L)` 2장 · `…(450*0*736*0 R)` 2장.

## 10. 검증 방법 (개발 시)

실제 PDF 없이 규칙을 바꾸면 반드시 깨짐.

### 파이썬·노드가 없는 PC 에서 (2026-09-22)

이 PC 에는 python·node 가 없습니다(윈도우 스토어 껍데기만 있음). **펄은 있습니다.**

1. `perl serve.pl 8777 <폴더>` 로 로컬 서버를 띄웁니다 (IO::Socket::INET 한 파일).
   `file://` 로 열면 브라우저가 스크립트를 막아 아무것도 못 잽니다.
2. 앱 HTML 과 라벨 PDF 를 같은 폴더에 두고 브라우저로 앱을 엽니다.
3. 파일 고르기 창을 거치지 않고 바로 물립니다:
   ```js
   const buf = await (await fetch('/label.pdf')).arrayBuffer();
   await openPdf(new File([buf], 'label.pdf', {type:'application/pdf'}));
   ```
4. 인쇄 배치는 `@media print` 규칙을 **미디어 조건 없이** `<style>` 로 얹은 뒤
   `getBoundingClientRect()` 로 잽니다. 상자·캔버스·오버레이가 같은지, 메모가 글자나
   절취선과 겹치는지 숫자로 확인할 수 있습니다.
   ⚠ **화면이 줄어든 상태로 재면 안 됩니다.** 메모 글자는 px 고정이라, 페이지가 작게
   보이는 상태에서는 상대적으로 커져 **없는 겹침이 있는 것처럼** 나옵니다.
   반드시 `--sheet-w`/`--sheet-h`(인쇄 크기)로 고정하고 재십시오.

### 옛 방법 (파이썬이 있는 PC)
- `pdfplumber` 로 PDF 글자를 조각 단위로 뽑아 JSON 저장 (`upright` 가 False 인 세로 글자 제외)
- 앱 HTML에서 `buildLines`, `mergeWrapped`, `rectsFor`, `findHits`, `applyRules` 등을 그대로 떼어 Node에서 실행
- 모든 품명 줄에 대해 "노랑이 없는 줄" 목록을 뽑아, 73(공용) 외에 남는 게 있는지 확인
- 마지막 전수 감사: PDF 5개 51페이지, 품명 줄 274개 중 261개 칠해짐, 13개는 전부 73(공용) — 정상
